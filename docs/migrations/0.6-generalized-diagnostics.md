# Migrating diagnostics from 0.5 to 0.6

Version 0.6 replaces the fixed quarterly casualty API with one definition-driven pipeline. This is an intentional pre-1.0 break: there are no aliases or dual call shapes.

Use `0.6.1` or later. The initial `0.6.0` publication described the current
preparation/review contract but did not consistently enforce it: selected
invalid periods, duplicate or incomplete losses could be omitted without
blocking review, and complete-period cutoffs did not execute. `0.6.1` corrects
those behaviors, preserves excluded and invalid records in the input audit,
and fails ambiguous arithmetic closed. No compatibility behavior from the
defective execution path is retained.

Install all five packages at one version:

```bash
npm install @actuarial-ts/core@0.6.1 @actuarial-ts/data@0.6.1 @actuarial-ts/interchange@0.6.1 @actuarial-ts/compliance@0.6.1 @actuarial-ts/agents@0.6.1
```

Core, data, interchange, and compliance support Node 20+. Agents and an all-five-package application require Node 22.13+, `@mastra/core >=1.51.0 <2`, `@mastra/mcp >=1.14.0 <2`, and Zod `^3.25.76`. The npm packages are lockstep `0.6.1`; Python and R adapters have their independent `0.2.0` generator version. Writers emit interchange `1.1.0`; readers continue accepting major version 1, and `diagnostic-definition` is the additive 1.1 kind.

## The new model

The flow is measure → formula template → bound instance → compiled definition → prepared/reviewed run → verified provenance.

```ts
import {
  CASUALTY_FORMULA_TEMPLATES,
  compileDiagnosticDefinition,
  createCasualtyMetricInstances,
} from "@actuarial-ts/core";

const instances = createCasualtyMetricInstances({
  counts: {
    reported: "reported",
    open: "open",
    closedNoPay: "closed-no-pay",
    closedWithPay: "closed-with-pay",
  },
  exposure: "earned-vehicle-years",
  amountBindings: [
    { id: "gross", paid: "gross-paid", incurred: "gross-incurred" },
    { id: "primary-250k", paid: "primary-paid", incurred: "primary-incurred" },
  ],
});

const compiled = compileDiagnosticDefinition({
  diagnosticDefinitionVersion: "1.0.0",
  id: "fleet-diagnostics",
  version: "1.0.0",
  lossRowGrain: "aggregate",
  measures,
  countPopulations,
  exposureBases,
  amountBases,
  derivedMeasures: [],
  formulas: CASUALTY_FORMULA_TEMPLATES,
  instances,
  reviewRules,
  periodAxis,
});
```

The old preset encoded `$250K` and primary inside formula IDs. In 0.6 those are ordinary caller-owned amount bases and bound measures. The reusable `paid-to-incurred`, `amount-per-exposure`, `amount-per-claim`, and `case-per-open` formulas do not change; calculation identities do.

## Input and execution changes

Use `sourceGroup` for incoming rows; `group` is reserved for mapped output. Exposure rows are long observations—one `measureId` and value per row—and declare `origin-static` or `valuation-specific` timing in the measure. Do not supply trusted development ages or policy-period labels: the compiled calendar or ordered period axis derives them.

```ts
import { runValidatedMetricDiagnostics, validateDiagnosticRunInput } from "@actuarial-ts/data";

const validated = validateDiagnosticRunInput({
  definition,
  losses: [{
    rowType: "aggregate",
    recordId: "row-1",
    sourceGroup: "fleet-a",
    origin: "2025",
    valuation: "2025-Q1",
    complete: true,
    source: { artifactId: "loss-run", sourceRow: 2 },
    measures: { reported: 4, "gross-paid": 100, "gross-incurred": 160 },
  }],
  exposures: [{
    key: "exp-2025",
    sourceGroup: "fleet-a",
    origin: "2025",
    measureId: "earned-vehicle-years",
    value: 20,
    complete: true,
    source: { artifactId: "exposures", sourceRow: 2 },
  }],
  filter: { sourceGroups: ["fleet-a"], instanceIds: ["casualty/count/reported-frequency"] },
  groupMap: { "fleet-a": "all-fleet" },
  groupDimensions: { "all-fleet": { region: "all" } },
  runPresetId: "annual-review-v1",
  datasetArtifactId: "loss-run",
});

const outcome = runValidatedMetricDiagnostics(validated);
```

Missingness is per measure (`unknown` or `zero`). Aggregation is always deterministic sum, then one division; a missing or non-positive denominator returns `null`. `filter.sourceGroups` is pre-map, `filter.outputGroups` is post-map, and `groupDimensions` attaches only to explicit output groups. Upstream code aligns loss/exposure policy periods; the removed `policyPeriods` field is not inferred.

Review warnings are declarative comparison/reconciliation/monotonic/layer-order/control-total rules. Every finding has a complete context including source unions, `developmentAge`, and `ageUnit`. A callback cannot hide unreviewed behavior. Structural review occurs before execution, and a blocked outcome cannot be stamped as complete.

## Provenance and interchange

```ts
import { createDiagnosticRunIdentity } from "@actuarial-ts/compliance";
import { diagnosticDefinitionToDoc } from "@actuarial-ts/interchange";

if (outcome.status !== "completed") throw new Error(`blocked at ${outcome.stage}`);
const provenance = await createDiagnosticRunIdentity({
  completedRun: outcome,
  inputArtifacts: [
    { id: "loss-run", assurance: "sdk-computed", bytes: lossRunBytes },
    { id: "exposures", assurance: "sdk-computed", bytes: exposureBytes },
  ],
  preparationArtifacts: [],
  preparationLineage: [],
});
const portableDefinition = diagnosticDefinitionToDoc(compiled, { createdAt: "2026-09-03T00:00:00Z" });
```

The removed flattened provenance helper accepted caller-restated fields and opaque extensions. `createDiagnosticRunIdentity` accepts only a data-owned completed run, hashes actual bytes for SDK-computed evidence, resolves separately scoped input/preparation artifacts and explicit lineage, reruns review/calculation, and returns owner-authenticated provenance. Serialized provenance must pass `verifyDiagnosticRunIdentity` before new bundle authoring; bundle verification independently checks its semantic fingerprint graph. FNV-1a identities are deterministic integrity aids, not cryptographic security controls; SDK-computed artifacts use SHA-256.

Quarterly aliases such as `2025Q1` remain readable at the boundary, but identity-bearing normalized output is canonical `2025-Q1`. Unknown executable definition fields, duplicate normalized CSV headers, impossible Gregorian dates, conflicting claim identity dates, non-finite triangles, unknown groups, and malformed/prototype-hostile JSON now fail closed.

## Agent tools

`defineActuarialTool` now parses raw `z.input` exactly once, gives the body `z.output`, and directly returns only the body result or a readonly failure envelope. Invalid input/output becomes `TOOL_INPUT_INVALID`/`TOOL_OUTPUT_INVALID`; an output schema that cannot preserve the failure union is rejected as `BAD_OUTPUT_SCHEMA`.

The diagnostic agent tool accepts only `runPresetId`, registered `instanceIds`, and a display `view`. The host owns the compiled definition, allowlist, run filters/grouping/cutoffs, and executor. A model cannot submit formulas, bases, populations, period rules, provenance, or a tenant ID.
