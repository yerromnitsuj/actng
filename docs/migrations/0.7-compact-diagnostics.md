# Using compact diagnostics in 0.7

The compact APIs were introduced in 0.7.0. Version 0.7.1 clarifies documentation and examples; it does not change formulas, review policy, or the replay wire format. Existing eager code remains supported: this is an optional, additive integration path, not another 0.5-to-0.6 breaking migration.

Install the four runtime packages together:

```bash
npm install @actuarial-ts/core@0.7.1 @actuarial-ts/data@0.7.1 @actuarial-ts/interchange@0.7.1 @actuarial-ts/compliance@0.7.1
```

These four support Node 20+. Install `@actuarial-ts/agents` at the same version only when needed; it requires Node 22.13+ and its documented Mastra/Zod peers. Its trusted diagnostic executor still accepts the eager completed-run/provenance contract; do not cast compact receipts into it. See the [agents package](../../packages/agents/README.md).

The [0.6 migration guide](0.6-generalized-diagnostics.md) remains the reference for definitions, measure/basis semantics, period axes, structural review, and the original breaking changes. The [formula catalog](../reference/diagnostic-formulas.md) is unchanged: ratio-of-sums, null denominators, scaling, and the six reusable casualty templates keep their existing meaning.

## Choose the API family deliberately

| Job | Eager API | Compact API |
| --- | --- | --- |
| Validate host input and prepare it through the data gateway | `validateDiagnosticRunInput` | `validateDiagnosticRunInputCompact` |
| Execute the validated input with policy gates | `runValidatedMetricDiagnostics` | `runValidatedMetricDiagnosticsCompact` |
| Core preparation/calculation when the host deliberately owns orchestration | `prepareDiagnosticData`, `runMetricDiagnostics` | `prepareDiagnosticDataCompact`, `runMetricDiagnosticsCompact` |
| Select an age / common maturity | `sameMaturity`, `commonMaturity` | `sameMaturityCompact`, `commonMaturityCompact` |
| Build verified provenance | Async `createDiagnosticRunIdentity`, with original artifact bytes | Async `digestDiagnosticArtifactChunks`, then synchronous `createCompactDiagnosticRunIdentity`, with authentic digest receipts |
| Portable evidence | Eager provenance / interchange BundleDoc APIs | `writeDiagnosticReplayStream` and `verifyDiagnosticReplayStream` |

Prefer the data gateway for application execution: it enforces validation, preparation, review, grouping, and the execution policy before issuing a completed run. Core calculations alone do not issue a data-owned completed receipt. Both families use the same mathematical implementation, but their authenticated owners are distinct and are not interchangeable call shapes.

For a small deliberate compatibility boundary, `materializePreparedDiagnosticData` and `materializeMetricDiagnosticsResult` produce complete eager prepared/result values from compact owners. They expand evidence and can be expensive. They do not turn a compact completed run into an eager completed run or make compact provenance a BundleDoc. Never materialize just to render a preview or obtain a maturity view.

## 1. Execute and handle both blocked outcomes

The following excerpts share the explicit [documentation fixture](../../tools/docs/fixtures/public-snippet-setup.mts): `definition`, `losses`, and `exposures` describe one aggregate row with four reported claims and 20 vehicle-years, observed at age 3 months. `lossRunBytes` and `exposureBytes` are the actual small fixture artifacts; `transformCommit` is caller-declared preparation evidence. These are host variables, not SDK exports. Supply your own mapped inputs in an application. The documentation checker typechecks and executes the excerpts against packed public packages.

Two illustrative review rules make one passing evaluation and one warning visible without changing the frequency calculation. Their thresholds are teaching examples, not actuarial recommendations.

```ts
import {
  commonMaturityCompact,
  sameMaturityCompact,
  type DiagnosticDefinition,
} from "@actuarial-ts/core";
import {
  getCompletedCompactDiagnosticRunInput,
  runValidatedMetricDiagnosticsCompact,
  validateDiagnosticRunInputCompact,
  type DiagnosticRunInput,
} from "@actuarial-ts/data";

function inspectCompactInput(input: unknown) {
  // Malformed input throws a validation error: show it before offering execution.
  const validated = validateDiagnosticRunInputCompact(input);
  const run = runValidatedMetricDiagnosticsCompact(validated);
  if (run.status === "blocked") {
    if (run.stage === "review") {
      // No result exists; review pages remain available to explain the block.
      return { kind: "review-blocked" as const, review: run.review };
    }
    // A metric-stage result exists for diagnosis, not as an accepted analysis.
    return { kind: "metric-blocked" as const, findingCount: run.result.findings.length };
  }
  return { kind: "ready" as const, run };
}

const compactDefinition: DiagnosticDefinition = {
  ...definition,
  reviewRules: [5, 3].map((threshold) => ({
    id: `reported-above-${threshold}`,
    kind: "compare" as const,
    code: "reported-threshold",
    description: `Reported exceeds illustrative threshold ${threshold}`,
    severity: "warning" as const,
    missingInput: "not-evaluated" as const,
    when: {
      left: { op: "measure" as const, measureId: "reported" },
      operator: "gt" as const,
      right: { op: "constant" as const, value: threshold },
    },
  })),
};
const compactExampleInput: DiagnosticRunInput = {
  definition: compactDefinition,
  losses,
  exposures,
  filter: { instanceIds: ["casualty/count/reported-frequency"] },
  groupMap: { fleet: "all-fleet" },
  runPresetId: "compact-documentation-v1",
  datasetArtifactId: "loss-run",
};
const selection = inspectCompactInput(compactExampleInput);
if (selection.kind !== "ready") throw new Error(`Analysis ${selection.kind}`);
const compactCompletedRun = selection.run;
const atThreeMonths = sameMaturityCompact(compactCompletedRun.result, 3, ["all-fleet"]);
const common = commonMaturityCompact(compactCompletedRun.result, ["all-fleet"]);
const ownedInput = getCompletedCompactDiagnosticRunInput(compactCompletedRun);
```

The selected frequency is `4 / 20 = 0.2`; no percent or per-million scaling is implied. `common.developmentAge` is 3 in this fixture. The ordinary warning is allowed by the default policy. Tightening the allowed review statuses can block the review; disallowing a metric finding can instead block at the metric stage. Neither branch may be passed to compact provenance creation. Do not loosen a policy merely to get a completed receipt.

`ownedInput` is the original deeply immutable **SDK-owned validated snapshot**, not the caller's mutable `losses` array and not a reconstruction of the prepared audit. Releasing all owners lets the runtime reclaim their private state; keeping a completed run retains its replay inputs. JSON, casts, object spread, worker messages, or another installed copy of the SDK do not restore owner authority. Across persistence/process boundaries, transfer plain inputs and validate again; use matching, deduplicated packages in one runtime for owner-based operations.

## 2. Read summaries, then page only the detail requested

Continue with `compactCompletedRun` from the preceding example. A report's check summaries include `findingCount`; the evaluation store separately records every passing, warning, failing, and not-evaluated evaluation. A check count, evaluation count, and finding count are different quantities. Use `effectiveStatus` for gate-facing categories; raw evaluation status also distinguishes `triggered` from `pass` and `not-evaluated`.

```ts
import {
  pageDiagnosticReviewEvaluations,
  pageDiagnosticReviewEvaluationSources,
} from "@actuarial-ts/core";
import {
  pageDiagnosticReviewFindings,
  pageDiagnosticReviewFindingSources,
} from "@actuarial-ts/data";

const review = compactCompletedRun.review;
const passing = pageDiagnosticReviewEvaluations(review.evaluations, {
  effectiveStatus: "pass",
  offset: 0,
  limit: 20,
});
const evaluation = passing.items[0];
const evaluationSources = evaluation
  ? pageDiagnosticReviewEvaluationSources(review.evaluations, evaluation.index, { limit: 20 })
  : null;

const findings = pageDiagnosticReviewFindings(review.findings, { limit: 20 });
const selectedFinding = findings.items[0];
const contextSources = selectedFinding
  ? pageDiagnosticReviewFindingSources(review.findings, selectedFinding.index, {
      location: "context",
      limit: 20,
    })
  : null;
const scopeSources = selectedFinding
  ? pageDiagnosticReviewFindingSources(review.findings, selectedFinding.index, {
      location: "scope",
      limit: 20,
    })
  : null;
```

Each page is `{ total, offset, items, nextOffset }`. Follow `nextOffset` with the same owner and query until it is `null`; do not treat a short preview as the full evidence. Use each item's **original `index`**, not its position on a filtered page, when opening sources. Keep that owner associated with the exact analysis; the host still enforces session, tenant, and current-analysis access when exposing HTTP pages.

| Collection | Supported selectors and source details |
| --- | --- |
| Core review evaluations | `ruleId`, `effectiveStatus`, `sourceGroup`, `origin`, `valuation`, `offset`, `limit`. Coordinate filters match either endpoint of a valuation pair, not control-total metadata. `scope.sourceCount` tells how many scope sources exist. |
| Evaluation sources | `offset`, `limit`; optional `overflowIndex` selects that expression overflow's sources instead of the ordinary scope sources. `expressionOverflowCount` identifies the available overflow entries. |
| Data review findings | `checkId`, `offset`, `limit`. It does not accept the core evaluation filter fields. Source-free finding summaries replace nested `sources` arrays with `sourceCount`. |
| Finding sources | `location: "context"` (default) reads the finding context's sources; `"scope"` reads `context.reviewScope.sources`. These are distinct lists. Each can be paged independently. |

All page APIs default to offset 0 and limit 100; limits must be integers from 1 through 1000, offsets nonnegative safe integers. Unknown query fields and forged owners fail validation. Source records retain their actual artifact/file/sheet/numeric-row/cell fields; absent fields are not invented. `getDiagnosticReviewEvaluation` / `getDiagnosticReviewFinding` and their `iterate...` counterparts return complete records with source lists. A single such record may be large, even if the caller requests only one. Prefer the page/summary APIs for UI work.

These stores cover **review** evidence. Metric-result `findings`, prepared cells/input audits, raw input snapshots, and numeric views still have ordinary retained structures. Compact does not mean constant-memory, and no dataset capacity is certified by this example.

## 3. Digest artifacts, create provenance, and verify a stream

This small example directly pipes the writer into the independent verifier. It does **not** collect the archive into an array, string, or buffer. The fixture's artifact bytes are already small in-memory values; in production the host should open repeatable file/storage streams and honor the same abort signal for pending I/O. The original fixture definition references `transform-script` for an externally pre-limited basis, so that caller-declared artifact must remain present even though it is not itself a computed-byte receipt.

```ts
import {
  assertVerifiedDiagnosticReplayStream,
  createCompactDiagnosticRunIdentity,
  digestDiagnosticArtifactChunks,
  verifyDiagnosticReplayStream,
  writeDiagnosticReplayStream,
  type DiagnosticReplayReadLimits,
} from "@actuarial-ts/compliance";

const controller = new AbortController();
const artifactBytes = new Map<string, Uint8Array>([
  ["loss-run", lossRunBytes],
  ["exposures", exposureBytes],
]);
function* artifactChunks(bytes: Uint8Array) {
  for (let offset = 0; offset < bytes.length; offset += 65_536) {
    controller.signal.throwIfAborted();
    yield bytes.subarray(offset, offset + 65_536);
  }
}
const inputArtifacts = await Promise.all(
  [...artifactBytes].map(([id, bytes]) =>
    digestDiagnosticArtifactChunks(
      { id, scope: "input", expectedByteLength: bytes.length, maximumByteLength: 1_000_000 },
      artifactChunks(bytes),
      { signal: controller.signal },
    ),
  ),
);
const compactProvenance = createCompactDiagnosticRunIdentity({
  completedRun: compactCompletedRun,
  inputArtifacts,
  preparationArtifacts: [{
    id: "transform-script",
    scope: "preparation",
    assurance: "caller-declared",
    algorithm: "git-sha",
    value: transformCommit,
  }],
  preparationLineage: [],
});
const limits: DiagnosticReplayReadLimits = {
  maximumEncodedBytes: 16_000_000,
  maximumArtifacts: 10,
  maximumRuns: 2,
  maximumArtifactBytes: 1_000_000,
  maximumInputDepth: 64,
  maximumInputNodes: 100_000,
  maximumInputStringUnits: 300_000,
  maximumInputTotalStringUnits: 1_000_000,
};
const replay = writeDiagnosticReplayStream({
  runs: [{ id: "fleet-review", provenance: compactProvenance }],
  openArtifact: (artifact) => {
    const bytes = artifactBytes.get(artifact.id);
    if (!bytes) throw new Error(`No retained bytes for ${artifact.id}`);
    return artifactChunks(bytes);
  },
  signal: controller.signal,
});
const verifiedReplay = await verifyDiagnosticReplayStream(replay, {
  limits,
  signal: controller.signal,
});
assertVerifiedDiagnosticReplayStream(verifiedReplay);
```

The reader verifies actual artifact bytes, revalidates inputs, reruns review/policy/math, and compares the entire canonical manifest/result content before returning. Success requires the trailer **and EOF**. `verifiedReplay.runs` contains small verified IDs/fingerprints, not restored completed-run owners. Keep computed digests authentic within the runtime; JSON copies of digest/provenance receipts do not acquire authority.

`preparationLineage: []` is appropriate here because the fixture directly identifies its input artifacts and declares its external basis transformation separately. When the host supplies derived files, add explicit edges connecting their output artifact IDs to the input and transformation artifact IDs; include every referenced artifact with the correct scope. The SDK checks graph consistency, not whether arbitrary CSV/XLSX bytes truly produced the submitted rows.

For a download, stream to a private temporary sink with backpressure, close it successfully before publishing it, and discard partial files on any error/cancellation. A later verification reads that file in chunks at most 128 KiB with the same resource policy. Writer artifact reads must be at most 64 KiB; digest-only reads may be larger and are processed through bounded copies. The numbers above are **fixture budgets**, not production defaults or a tested capacity promise. Choose limits for your host and see the [resource/cancellation contract](../reference/diagnostic-replay-stream.md#required-resource-policy).

Abort is cooperative between chunks/phases, not an interruption of synchronous hashing, provenance replay, or actuarial calculation. Pending host reads must also receive the signal. Use a worker/process if CPU interruption is required. Never emit a successful analysis/export receipt after a blocked run, failed stream, or incomplete verification.

## Preserve version and assurance boundaries

- Retain matching core/data/compliance versions for saved stream verification. The reader recreates version-bearing manifests with its installed engines; an unchanged `diagnostic-replay/1` wire format does not promise verification across SDK releases, including 0.7.0 to 0.7.1. Preserve the original verifier/lockfile; do not edit stamps or recompute tags to hide a mismatch.
- Eager/compact normalized identity parity applies to equivalent inputs **under the same SDK version**. Version-stamped run/binding identities change across releases even when the numerical calculation identity is unchanged.
- Artifact SHA-256 proves the bytes received match the digest, not authorship, source truth, an independently checked transformation, or correct claim-level capping. Caller-declared evidence stays explicitly declared. Replay establishes internal reproducibility, not an actuarial opinion or a digital signature.
- Keep the wire formats distinct: interchange remains 1.1.0; this stream is `diagnostic-replay/1`; Python/R generator versions are independent. See the [full replay reference](../reference/diagnostic-replay-stream.md) and [versioning policy](../../VERSIONING.md).
