## 2. Non-negotiable implementation rules

1. Add the smallest public-API failing regression before each production fix.
2. Never use ordinary object inheritance as a registry or map membership test.
   Prototype-like identifiers remain legal; use `Map`, null-prototype records,
   or an own-property test.
3. Never encode tuples by concatenating caller strings with a delimiter. Use
   nested maps or canonical structured tuple keys after validation.
4. Every external value is validated and defensively snapshotted before the
   SDK stores it, hashes it, freezes it, or crosses an `await`.
5. A validated/branded value means no later deterministic configuration check
   can reject it. Execution may report data findings, but must not discover a
   boundary-validation omission.
6. Structural uncertainty never becomes a number. Allowing a fail status can
   permit a reviewed output, but it cannot unblock affected arithmetic.
7. Opaque same-major interchange fields may round-trip; semantic readers must
   refuse unknown executable behavior.
8. Published values, frozen migration evidence, and source-derived artifacts
   are immutable anchors. Tolerance or fixture changes require a named source,
   printed-precision rationale, and explicit review; code drift is never a
   reason to regenerate them.
9. The release gate must be mechanically required by publishing, not merely
   documented as a command a person should remember.

## 3. Decisions that do not require an owner interview

The audit exposed two underspecified policies, but both have a clear safe
resolution consistent with the SDK's purpose:

- Duplicate headers after semantic normalization are rejected atomically,
  even if the two columns currently contain equal values.
- Any field documented as an ISO calendar date must represent a real Gregorian
  date, not merely match a digit pattern.

Other apparent choices are already resolved by repository policy: the
normative diagnostic specification wins over accidental 0.6 implementation
shapes, legal prototype-like identifiers must work, and correctness is not
constrained by preserving 0.5 consumers. No blocking owner question remains
for planning. If implementation uncovers a genuinely different actuarial
method choice—most plausibly in reproducing Mack 1999 tail standard error—stop
with the source formula, current formula, numeric difference, and migration
impact before choosing a substitute method.
